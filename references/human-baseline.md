# 人写语料基线（中文核心期刊全文）

`style_lint.py` 的门禁阈值不是凭手感设定的红线，而是从真实人写论文里量出来的分布。
阈值存放在 `scripts/corpus/baseline.json`，
由 `scripts/corpus/build_baseline.py` 用 `style_lint.py` 自身的统计口径生成；本文件记录语料来源、
测量口径与分位数表，改阈值前先看这里。

## 一、语料

| 项 | 值 |
|---|---|
| 学科 | 以工科、计算机与物理为主 |
| 篇数 | 165 篇（综述 78 + 研究型 87） |
| 年份 | 2015 年以后（页眉区间内最大的合理年份） |
| 抓取方式 | 期刊官网 PDF 全文 |
| 入选条件 | 正文 ≥3000 字且句数 ≥40（`corpus_stats.py`） |

正文提取只保留中文主体：剔除标题行、图表题、参考文献、基金与作者简介、编号章节行，
再按上一行是否以句末标点收尾把明显短于常行的物理行合并回段落。
PDF 抽出的文本会带私用区字符与丢失的软连字，这部分残留会被 A1 隐形字符规则命中，
统计时保留原样，不做人工清洗，因此人写不通过的篇目里有 10 篇是被取字噪声拖下去的。

## 三、阈值取法

- **门禁（退出码 1）取 p99。** 超过 p99 意味着该稿在这一项上比 99% 的已发表论文更极端，
  此时判违规才站得住。命令行显式给出 `--colon-k` 一类参数时覆盖基线值。
- 比较在打印精度上做：`round(value, 2) > cap`。否则处在 p99 位次的那篇论文会被自己定出来的
  阈值判死，并打印出「0.50 > 0.50」这种无法整改的消息。
- **人写语料自身的通过率 73.3%**（不计 F9～F11 与 C6 书写口径，见第四节与第九节）。不通过的 44 篇里，
  10 篇只因 PDF 取字残留的隐形字符，13 篇因用词类别超 p99（7 个类别各有 1～2 篇在 p99 之上），
  其余每条密度门禁各命中 2～3 篇（1.2%～1.8%），与 p99 的定义一致。
  门禁条数越多，人写稿被某一条误伤的概率越高，这是逐项取 p99 的代价；遇到只超一项且超得不多的
  情形，先看逐处清单再动手。
- **B 级分布偏离取 p10 与 p95 双边。** 低于 p10 记过净，高于 p95 记过密，只提示不阻断。
  覆盖 14 项密度加 4 项形态。人写语料的偏离项数分布：
  0 项 21.8%、1 项 33.3%、2 项 18.2%、3 项 14.5%、4 项 6.7%、5 项 3.0%、6 项 1.2%、7 项 1.2%。
  所以偏离 ≥4 项时提示按清单回填，这个水平只有 12.1% 的人写论文达到。
  报告里的这组百分比由基线 json 的 `deviation` 字段现算，换基线即随之改变。
- **严禁项有四条**：非并列类未豁免斜杠、隐形字符、英文摘要中文标点、C6 图表括注。
  其中隐形字符在语料里只出现于 PDF 取字残留；斜杠与英文摘要两条在本语料上零观测，
  属于按定义判死而非按语料验证过的项，见下节；C6 是书写口径，见第九节。

## 四、语料未覆盖的四处

1. **非并列类未豁免斜杠**：`slash_hits` 穷举后只产生 标准代号 / 物理单位 / 分数比例 /
   并列替代 / 英文串联 五类，默认豁免前四类之外的四项，剩下并列替代走密度，
   因此默认配置下该硬门禁恒不触发。收紧 `--allow-slash` 时它才有意义。
2. **英文摘要中文标点（F6）**：`EN_PAT` 要求行首为 Abstract / Keywords（可带加粗），
   语料的英文摘要行在抽取时已被剔除，该门禁从未在人写语料上执行过。
3. **法规文件名与标准名称**：按 GB/T 15834，法规、规划、意见、方案一类文件名必须用书名号；
   按 GB/T 1.1，标准正式名称跟在编号或「国家标准」一类限定语之后加书名号亦属规范。
   `book_mark_hits` 将两者分别定性为 法规文件 与 标准名称 并排除在密度之外；孤立的《或》定性为 单书名号，
   同样不计密度，只在逐处清单里列出。
4. **量值书写（F9 / F10 / F11）**：语料取自 PDF 抽字，千分空、单位前的空隙与全半角波浪号
   在抽字时或被丢掉、或被规范化，无法据此统计人写论文的真实比例（按默认口径复跑，
   165 篇里 93 篇报「数值与单位贴合」、43 篇报「半角波浪号」，多半是抽字吞空格与字形归一）。
   因此这三项的判据全部来自标准条文（GB/T 15835 第 8.1 四位以上可分节、第 8.5 数值不得断开
   移行、第 10 条代号序号不分节；GB 3101 数值与单位间留一空隙；GB/T 15834 4.13.2 浪纹线为
   全角 ～），不是语料分位数，也不计入第三节的通过率。
   F9 默认口径 `--num-group=plain`：四位以上数值一律写 1200，写成 1 200 判违规，
   `grouped` 反向，`either` 只判混用；代号、序号与年份被分节在三种口径下都违规。
   F10 默认口径 `--unit-space=space` 与 `--qty-lead=tight`：只有数值与计量单位之间留空，汉字与数值一律贴合，
   写成 `下游6～8 m处`、`较2000年增长约122%`；不带单位的年份、百分数、计数只查留空一侧，space 口径不追究；
   百分号前留空在任何口径下都违规。切到 `either` 时退回只判同一稿件内混用。型号名里的数字
   （YOLOv5s、ResNet50）不当量值。单位表含上标面积、体积单位（m²、m³、Mm³）。
   F11 是唯一有外部正解的一项：半角 `~` 用作数值范围一律违规。

## 四之二、可读性三项（A13～A15）的语料对照

2026-09 重抓语料，取回 127 篇（综述 56 / 研究型 71，其余站点拒绝下载），
用当前检测器量得：

| 指标 | p50 | p90 | p95 | p99 | max | 命中篇数 |
|---|---|---|---|---|---|---|
| A13 压缩简称（每千字） | 0 | 0.45 | 0.58 | 2.25 | 4.54 | 43 / 127 |
| A14 术语首现未解释（每篇个数） | 0 | 4 | 4.7 | 6.74 | 9 | 54 / 127 |
| A15 抽象名词施事（每千字） | 0 | 0 | 0 | 0.06 | 0.10 | 6 / 127 |

对照：`references/plain-speech.md` 第一至三节 15 条原句合计约 0.26 千字，A13 为 34.6/千字、A14 为 11 个、
A15 为 11.5/千字，三项都远超人写 p99；对应改句分别为 0、3、0。改句剩下的 3 个 A14（非极大值抑制、
先验、正样本）属目标读者已熟悉的术语，可用 `--known-terms` 剔除。

取法与局限：

1. 三项只告警、不进门禁、不进 B 级。词表与领域强相关：人写语料命中的 A13 多为通信、控制稿里的
   裸用"时延"（189 处），对这类稿件是规范术语，用 `--known-terms=时延` 剔除即可。
   "时延""粒度"带限定语（通信时延、端到端时延、细粒度、多粒度）时不计，"安全量化"一类跨词误切已排除。
2. A14 是"首现清单"而非密度：每个术语全文只报一次。一篇讲机器学习方法的综述报十几个属正常，
   逐条按目标读者判断补不补"即……"；读者熟悉的术语用 `--known-terms` 剔除，本文领域术语用 `--terms-file` 追加。
3. A15 在人写语料里极少（p99 0.06/千字），命中的几处（需求推动了技术创新、特性催生了插件生态）
   与病例同型，精度最高，命中即应看。
4. 名词串（长定语链）试过按小句内"的/与"个数与长度判，病例与改句分不开，人写论文里
   "提出了一种基于……的……网络"又极常见，故未收入脚本，只在 `plain-speech.md` 第四节列为人工审查项。

## 五、为什么不用一刀切清零

早期版本把一字线、双引号、书名号、正文冒号全部要求清零。用真实语料一验，
这套口径会把 90% 的已发表中文核心期刊论文判成不合格：人写论文里 17 处一字线、
46 处弯引号、21 处正文冒号都是常态。清零口径真正的效果不是让稿件更像人写，
而是把稿件洗成一种标点贫乏、句长均匀、全靠连词推进的机器腔。
因此本脚本改为按人写分布判密度，并对清洗过度单独给出过净提示。
用词也一样：「值得注意的是」在 165 篇里有 49 篇用过，「综上所述」47 篇，「至关重要」52 篇，
单次出现不能当 AI 痕迹，只有密度超过人写 p99 才算。

## 六、用词词表阈值（V 级）

词条与改法在 `scripts/lexicon.tsv`，每条词、每个类别都按篇计每千字密度（未出现记 0）取分位数，
存于基线 json 的 `lexicon` 字段。判法：

- 单词：全文 ≥2 处且密度超过该词人写 p99，告警「超人写」；
- 同段：同一段内同类别 ≥2 处，告警「同段堆叠」；
- 类别：全文 ≥2 处且类别密度超过人写 p99，进门禁。

| 用词类别 | 用过的篇数 / 165 | p95 | p99 |
|---|---|---|---|
| 空转套话 | 141 | 0.49 | 0.66 |
| 程度虚词 | 139 | 0.89 | 1.14 |
| AI高频修辞 | 77 | 0.28 | 0.55 |
| 本质论断 | 62 | 0.18 | 0.26 |
| 口语漂移 | 39 | 0.18 | 0.40 |
| 空洞黑话 | 29 | 0.12 | 0.26 |
| 文言腔 | 11 | 0.04 | 0.11 |

空洞黑话在人写语料里罕见：165 篇中只有 29 篇出现过任一词条，p99 仅 0.26/千字，
「证据缺口」「兜底」「技术可得」「检索性判断」在语料里都没有出现过 6 篇以上。
单词的最大值可能来自正当的专业用法（如某篇网络论文里「全链路」达 4.31/千字），
所以单词只告警，门禁按类别判。

增删词条后须重跑 `build_baseline.py`，否则新词在基线里没有阈值，按 p99=0 处理。

## 七、重建基线

语料全文因版权不随技能分发。要按自己的语料（例如目标刊论文）重建基线：

```bash
# 1. 自备全文 PDF，抽成纯文本放进 <workdir>/txt/（文件格式见 corpus_stats.py 文档串），
#    再提取正文，产出 <workdir>/md/*.md（stats.jsonl 含可读性三项 jargon_k / terms / actor_k）
python scripts/corpus/corpus_stats.py <workdir> 2015

# 2. 用当前检测器重测语料，写出基线 json，stdout 打印本文件第二、六节的表
python scripts/corpus/build_baseline.py <新基线>.json <workdir>/md --source="<语料说明>"
```

`<workdir>` 是一次性工作区，不必保留。运行 `style_lint.py` 时用 `--baseline=<新基线>.json` 指定。

改动任何检测器（尤其 `dash_hits` 的 kind 判定、`authority_hits` 的引标窗口、
`book_mark_hits` 的豁免集）或 `lexicon.tsv` 之后，基线 json 与本文件的表必须重算，
否则阈值会被上一版检测器的误分类锚死。

## 八、C4 节号回指与 C5 压缩句的来历

起因是一类综述稿的段首句「读不动」：句子不长，词层面的名词比、虚词比、名词串密度也与人写无差别，
差在句子结构。按句逐项对比 267 篇人写语料（jieba 分词、`style_lint.sentences` 断句），人写综述的分布如下，
问题稿在这几项上都明显偏离：

| 特征 | 人写综述 |
|---|---|
| 段首句含「x.x节 / 第x节」 | 0.6% |
| 全文节号回指（每千字） | 中位 0.05 |
| ≥50 字句不含「的」 | 4.7% |
| 「的」每千字 | 中位 32.2 |

人写论文的做法：结构路线图单独成句放在引言末尾（「本文结构安排如下：第1节…；第2节…」，
中位 136 字、只交代结构）；正文段首句只立话题，节号几乎不出现；需要回指时复述内容。
所以 C4 逐条只列段首句与一句多处的回指，路线图句不列；C5 只看「一个『的』都没有的长句」这一极端，
不对「的」的密度设门禁（人写之间差别本来就大）。

被排除的候选：一句 ≥2 个因果动词（推动/导致/使得…）、名词串（≥3 个名词直接相连）密度，
两者在问题稿与人写之间都不区分，未做成规则。

## 九、C6 图表括注

规则来自 `checks.md`「图表引述融入句子」，不是语料分位数。判据：括号内容剥掉 `[n]` 引用后，
以图表号开头、含「见/如＋图表号」或以图表号收尾，即 `（图3）`、`（图9④）`、`（见表1）`、
`（如图8蓝色部分所示）`、`（R=0.019，见图4(c)）`、`（见图13(a)[4]）` 一类；允许一层内嵌括号装分图号。

267 篇人写语料按此口径复跑（图题、表题行除外）：77 篇（28.8%）至少出现一处，共 282 处，
全文密度 p50 0、p90 0.22、p95 0.53、p99 1.31 处/千字。按 p99 设门禁等于放行，所以 C6 与 F9～F11
一样按书写口径判严禁，不计入第三节的通过率（`build_baseline.py` 的 `CONVENTION` 含「图表括注」前缀）。

括号里提到图表、但图表号既不在开头也不在结尾、又没有「见/如」引出的说明语不判。语料里这类只有 3 处：
`(与图1(c)中标记的上表面对应的面)`、`(即位置偏上的点，图18中下侧的圆点)`、
`(为了方便作图和阅读，图8中的点代表…)`。「图像」「地图3张」「代表1类」一类不含图表号的括号，
以及句内的 `如图2(a)所示` 里的分图号括号，都不命中。
