# zh-paper-polish

面向中文学术论文的润色 skill，供 Claude Code 等支持 skill 的编程 agent 使用。它把润色、去 AI 味、去重三件事放进一套规则，另附两个可复算的脚本。`style_lint.py` 按165篇中文核心期刊人写全文的实测分布判文风，`polish_diff.py` 对照改前改后核验引用、段落与数值。

## 一、能做什么，不做什么

能做：

- 逐段润色已成稿的中文正文，原文通顺就原样输出，不为换词而换词。
- 查用词中的机械套话与空洞黑话，以及段落里的跨段提纲式报数和先总后分骨架。
- 查节号回指、压缩句、图表括注、术语漂移和缩写首现。
- 按 GB/T 15834、GB/T 15835、GB 3101 查标点与量值的书写，包括破折号、斜杠、冒号、分号和书名号的用法，以及多位数分节、数值与单位的间隔和全角浪纹线。
- 做可读性审查，找出压缩简称、首次出现却没有解释的术语，以及抽象名词作主语的句子。
- 断言强度跟证据走；可能改变原意的改动单列为「原意风险」，交作者确认。
- 改完用 `polish_diff.py` 核验，只要引用的序列、段数或受保护的段落（标题、图题表题、关键词、参考文献）有任何变化，就判不通过。

从零起草、英文写作、改实验数据或结论、排版与格式装配，都不在本 skill 的范围内。

## 二、安装

把整个目录复制到 agent 的 skills 目录，例如 Claude Code：

```bash
git clone https://github.com/DawnJson/zh-paper-polish.git ~/.claude/skills/zh-paper-polish
```

其他 agent 放进各自的 skills 目录即可，入口是 `SKILL.md`。

依赖：

| 用途 | 依赖 |
|---|---|
| `style_lint.py` 读 Markdown、纯文本 | Python 3 标准库 |
| 读 `.docx`（`style_lint.py` 与 `polish_diff.py`） | `python-docx` |
| `polish_diff.py --pages`（用 Word 复核页数） | Windows、`pywin32`、Microsoft Word |

脚本路径相对 skill 目录。`--pages` 取不到 Word 时在报告里写明跳过原因，不算失败。

## 三、快速上手

```bash
cd ~/.claude/skills/zh-paper-polish

# 文风门禁：通过退出码 0，门禁不通过 1，文件、基线、词表缺失或族名写错 2
python scripts/style_lint.py examples/before.md
python scripts/style_lint.py examples/after.md
python scripts/style_lint.py 稿件.docx

# 改前改后对照核验：通过 0，硬检查失败 1，文件缺失、类型不一致或读取失败 2
python scripts/polish_diff.py examples/before.md examples/after.md
```

逐处清单默认写到当前目录的 `_stylelint.txt` 与 `_polishdiff.txt`（`--report` 可改），摘要打印到 stdout。

示例（`examples/before.md` 与 `examples/after.md`）：

**改写前**

> 随着深度学习技术的不断发展，目标检测在工业质检领域具有重要的理论意义与应用价值。值得注意的是，现有方法主要存在三个方面的问题，下文依次讨论。首先，小目标特征微弱——在深层网络中容易丢失；其次，样本分布呈现长尾特性，尾部类别召回率偏低；最后，模型部署到边缘设备时面临时延挑战（见2.3节）。研究表明，引入注意力机制能够显著提升检测精度。张三等[12]通过引入多尺度特征融合，实现了对小目标的有效检测，在公开数据集上达到了91.2%的mAP。李四等[13]通过引入重加权损失，使尾部类别召回率提升了4.1%。综上所述，本文提出的方法深度赋能工业质检，形成了检测与反馈的协同闭环，为后续研究奠定了坚实基础。

**改写后**

> 工业质检中的目标检测仍有三处难点。小目标的特征微弱，经深层网络多次下采样后容易丢失。样本分布呈长尾，尾部类别的召回率偏低。模型部署到边缘设备后，推理耗时也受到限制。引入注意力机制可以提升检测精度[待补引]。张三等[12]融合多尺度特征检测小目标，在公开数据集上的mAP达到91.2%。李四等[13]改用重加权损失，即加大尾部类别在损失函数中的权重，使尾部类别的召回率提升了4.1%。本文方法把检测与反馈连成闭环。

各检查项的口径与可调参数（`--terms`、`--abbr-known`、`--baseline`、各项阈值覆盖）见 `references/checks.md`，或 `python scripts/style_lint.py --help`。

## 四、基线

默认基线 `scripts/corpus/baseline.json` 取自2015年以后发表的165篇中文核心期刊人写全文（综述78篇、研究型87篇），学科以工科、计算机与物理为主。

- 门禁取人写论文的 p99，超过门禁说明该项比99%的已发表论文更极端。
- B 级提示比对人写论文的 p10 与 p95，低于 p10 记为过净（稿子被洗得过于干净），高于 p95 记为过密，只提示不阻断。
- 人写语料自身的门禁通过率为73.3%（不计量值书写与图表括注两类书写口径）。门禁越多，人写稿被某一条误伤的概率越高；只超一项且超得不多时，先看逐处清单。

论文全文因版权不随 skill 分发。要按自己的语料（例如目标刊论文）重建基线，步骤见 `references/human-baseline.md` 第七节；分位数表、阈值取法与各门禁的来历也在这份文件里。

改了检测器或 `scripts/lexicon.tsv` 后必须重跑 `build_baseline.py`，否则新增的词条在基线里没有阈值，p99 按0计。

## 五、局限

- 各项按每千字计，短文本的密度会失真，几百字的片段里一两处符号就会越线。门禁结论以整节或全文为准。
- `--pages` 只在装有 Word 与 `pywin32` 的 Windows 上可用；其余平台照常核验，只跳过页数。
- 阈值来自上述语料，偏工科、计算机与物理。目标刊的口径不同时，可以用该刊论文自建语料，用 `build_baseline.py` 生成基线，再以 `--baseline=<新基线.json>` 运行。
- 多位数分节、数值与单位的间隔、浪纹线这几项门禁取自国标条文，图表括注是本 skill 的书写口径，都不是语料分位数，出现即判。
- 逻辑断层、词表之外的新造黑话、学科专有的同义换名、读者层次错位，脚本查不出，靠 `SKILL.md` 的人工审查环节。
- 这是文风检查器，不是作者身份或 AI 生成判别工具。脚本只说明某项指标偏离了人写分布；基线语料里的人写论文本身也有26.7%过不了门禁（不计书写口径）。不要用它判断某人是否用了 AI。
